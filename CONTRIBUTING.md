# Contributing

Keep contributions reproducible and architecture-aware. A new example should include editable JSON or native TeX, evidence/assumptions, and rendered outputs. Treat examples as illustrative unless backed by a specific implementation or source.

Run the portable tests and rebuild affected figures. Inspect actual images at full resolution and at their intended display width. Do not report the geometry linter as proof of semantic or visual correctness. For a bug report, include the smallest relevant spec, the command, tool versions, expected behavior, and actual output; omit private architecture details and credentials.

Prefer original code. For copied/adapted upstream material, record exact repository, revision, source file, modifications, and license obligations in the attribution inventory. Do not bring custom academic-only code into the MIT implementation. Keep the portable skill compact; detailed agent instructions belong in its reference files, while human installation and project documentation belong outside the skill directory.
